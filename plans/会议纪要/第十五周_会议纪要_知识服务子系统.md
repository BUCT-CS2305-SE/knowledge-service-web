## 四、技术/协作决策

- **决策1（认证体系统一）**：三个子系统（知识服务/知识问答/后台管理）统一采用 Bearer Token 认证方案。Token 由后台管理子系统（子系统5）统一签发，知识服务子系统（子系统2）和知识问答子系统（子系统3）共享同一认证体系。登录入口统一在本子系统，登录成功后 token 存储至 localStorage，跨子系统请求均携带 `Authorization: Bearer <token>` 请求头。

- **决策2（跨系统 token URL 传递方案）**：由于知识服务子系统与知识问答子系统部署在不同域名下，localStorage 无法跨域共享。本子系统采用 URL 参数传递方案——从 localStorage 读取 `auth_token`，经 `encodeURIComponent` 编码后附加到问答子系统跳转 URL 的 `?token=` 参数中。问答子系统从 URL 参数读取 token 后存入自身 localStorage，完成认证状态同步。

- **决策3（问答入口设计）**：在 Header 导航栏右侧（搜索按钮左侧）新增"知识问答"按钮，采用金色边框+金色文字样式与系统整体设计风格一致。桌面端显示为 `[💬 知识问答]` 按钮，移动端在汉堡菜单中显示为独立菜单项。点击后在新标签页打开问答子系统，并通过 URL 参数传递 token。不修改路由系统，不新增页面路由。

- **决策4（数据迁移策略）**：用户收藏和评论数据从 localStorage 迁移至后台数据库时，采用"增量同步"模式——首次全量导入后，后续仅同步新增或修改的记录。迁移过程保留客户端本地副本作为回滚备份。

- **决策5（接口规范对齐机制）**：由赵子皓负责汇总三个子系统接口规范不一致之处，形成《跨子系统接口规范对齐表》文档，统一提交至课程负责人协调。主要包括：字段命名统一（camelCase vs snake_case）、分页参数统一（page/size vs offset/limit）、错误码规范统一。

- **决策6（联调优先级排序）**：联调工作按以下优先级推进——P0：用户认证联调（阻塞所有需登录的功能）；P1：文物数据接口联调（核心功能依赖）；P2：知识问答入口与 token 传递（跨系统联调）；P3：数据迁移与统计看板对接（优化类功能）。

## 六、其他讨论内容

1. **关于教师反馈的改进方向**：小组汇报后教师提出了以下改进建议，已作为联调阶段的工作重点纳入本周计划：（1）当前系统各子系统间的衔接不够紧密，建议在知识服务子系统中增加与知识问答子系统的交互入口——已在 Header 组件中实现"知识问答"跳转按钮，点击后新标签页打开问答系统并自动传递 token；（2）登录认证应统一使用后台管理子系统的用户体系，避免各子系统独立维护用户数据——已在本周完成与子系统5的用户认证接口联调，替换了原有的 localStorage Mock 认证；（3）数据展示应体现多源融合的特性——知识图谱查询结果页面已预留与问答系统的联动入口（KG 节点详情面板中可一键跳转至问答页并预填文物上下文）。

2. **关于跨系统 token 传递的技术细节**：本子系统采用 URL query string 方式向知识问答子系统传递 token（`http://10.4.163.140:5173/?token=<encoded_token>`）。该方案的前提是问答子系统能正确解析 URL 中的 `token` 参数并写入其自身的 localStorage。需与知识问答组确认：（1）问答子系统是否已实现 URL token 参数的读取逻辑；（2）token 读取后是否立即存入 localStorage；（3）token 在 URL 中的暴露风险——建议问答子系统在读取 token 后使用 `window.history.replaceState` 清除 URL 中的 token 参数，避免 token 残留在浏览器历史记录中。

3. **关于联调协作机制**：鉴于三个子系统分属不同小组开发，联调过程中容易出现"互相等待"的情况。会议决定采取以下措施：（1）本子系统主动推进联调，不等其他子系统先行改动；（2）在 `authService.ts` 和 `artifactService.ts` 中保留 Adapter 兼容层，同时支持 Mock 数据和真实 API，确保单个子系统不可用时不影响其他功能；（3）每周三通过微信群向其他子系统同步联调发现的问题和修复进展，避免信息不对称；（4）联调发现的问题统一记录在 GitHub Issue 中并 @ 对应子系统负责人。

4. **关于文物ID映射问题**：知识问答子系统返回的 `relatedArtifacts` 字段使用的是知识图谱组内部的实体 ID（如 `entity_12345`），而非本子系统的文物 ID（如 `artifact_001`），导致问答结果中的相关文物卡片无法正确跳转到详情页。需与知识图谱组协商以下三种方案之一：（1）在 CSV 数据的 `id` 字段保持统一；（2）知识问答子系统在返回结果中额外提供本子系统兼容的文物 ID；（3）本子系统维护一份实体ID→文物ID的映射表。优先推荐方案（1），从根本上消除 ID 不一致问题。
